# Park Builder

브라우저에서 즐기는 아이소메트릭 테마파크 경영 시뮬레이션입니다. 길을 깔고 놀이기구와 매점을 지어 손님을 맞이하고, 요금과 입장료를 조절해 공원을 키우세요.

TypeScript + Vite + Canvas 2D로 만들었고 런타임 의존성이 없습니다. 그래픽은 모두 코드로 그리며 외부 에셋이 없습니다.

## 실행

```bash
npm install
npm run dev      # 개발 서버 (http://localhost:5173)
npm test         # 단위 테스트
npm run build    # 타입 체크 + 프로덕션 빌드 (dist/)
```

Node.js 18 이상이 필요합니다.

## 목표

**4개월 안에 손님 100명과 공원 평점 650을 동시에 달성하고, 그 상태를 하루 동안 유지하세요.**

- 기한을 넘기거나 잔고가 **3일 연속 마이너스**면 게임이 끝납니다.
- 결과 화면에서 새 게임을 시작하거나, 목표 없이 계속하는 **자유 모드**를 고를 수 있습니다.
- 시작 자금은 ₩10,000입니다. 놀이기구를 전부 한꺼번에 살 수는 없으니, 번 돈으로 조금씩 키워 가야 합니다.

## 조작법

| 입력 | 동작 |
| --- | --- |
| 툴바 버튼 | 길 / 놀이기구 / 매점 / 장식(쓰레기통 포함) / 지형 올리기·내리기 / 철거 도구 선택 (같은 버튼을 다시 누르거나 `Esc`로 해제) |
| 툴바 `직원` → `청소부 고용` / `정비공 고용` | 도구가 아니라 즉시 실행: 공원 입구에서 직원이 나타남 |
| 왼쪽 클릭 | 건물 설치·철거 |
| 왼쪽 드래그 (길 도구) | 직선으로 길 깔기 |
| 왼쪽 드래그 (장식 도구) | 직선으로 나무·꽃·쓰레기통 놓기 |
| 왼쪽 클릭·드래그 (지형 도구) | 칸마다 높이를 1단계 올리거나 내림 (드래그는 직선) |
| `R` | 설치할 건물 회전 |
| 트랙 편집 중 `↑` `←` `→` `PgUp` `PgDn` `C` `B` `L` | 직선 / 좌 / 우 / 오르막 / 내리막 / 리프트 / 브레이크 / 루프 조각 잇기 |
| 도구 없이 건물·손님·직원 클릭 | 정보 패널 열기 (요금 조절, 철거는 건물 패널에서, 직원 패널에서 `해고`) |
| 오른쪽/가운데 드래그, `WASD`, 방향키 | 카메라 이동 |
| 마우스 휠 | 줌 |
| `Space`, `1` `2` `3` | 일시정지, 1배속, 2배속, 4배속 (상단 버튼과 동일) |
| `Esc` | 드래그 취소 → 도구 해제 → 선택 해제 |

## 게임 규칙

**시작 가이드**
- 새 게임을 시작하면 왼쪽 위에 체크리스트가 나옵니다: 길 깔기 → 놀이기구 → 매점 → 첫 손님 → 요금 바꿔 보기, 그리고 선택 과제로 롤러코스터 완성. 지금 해야 할 단계의 설명이 나오고 눌러야 할 툴바 버튼이 깜빡입니다. 한 번 달성한 단계는 나중에 철거해도 유지됩니다.
- `▾`로 접고 `×`로 닫을 수 있고(상단 `?` 버튼으로 다시 열기), 필수 5단계를 마치면 축하 문구와 함께 잠시 뒤 저절로 닫힙니다. 가이드 이전에 저장된 공원을 불러오면 가이드를 띄우지 않습니다.

**건설**
- 건물의 **입구(노란 칸)** 가 공원 입구에서 이어진 길에 닿아야 운영됩니다. 끊기면 빨간 칸으로 바뀌고 손님이 오지 않으며 유지비만 나갑니다.
- 철거하면 건물은 건설비의 50%, 길은 ₩5를 돌려받습니다.

**롤러코스터 (직접 설계)**
- 놀이기구 중 `롤러코스터`를 고르면 역(3×1)이 설치되고 곧바로 **트랙 편집 모드**로 들어갑니다. 열차는 역의 노란 입구 쪽이 아니라 **역이 향한 방향**(`R`로 회전)으로 출발합니다.
- 하단 팔레트나 단축키로 조각을 한 칸씩 이어 붙입니다: `↑` 직선, `←` 좌회전, `→` 우회전, `PgUp` 오르막, `PgDn` 내리막, `C` 체인 리프트, `B` 브레이크, `L` 루프. `Backspace` 되돌리기(전액 환불), `Enter`/`Esc` 편집 종료. 편집 중에는 방향키 대신 `WASD`로 카메라를 움직입니다.
- 열차가 **역의 시작 칸으로 역이 서 있는 땅 높이, 같은 방향으로** 돌아오면 코스가 완성되고 운행을 시작합니다(입구에 길을 이어야 손님이 옵니다). 완성된 코스터는 건물 패널의 `트랙 편집`으로 다시 고칠 수 있고, 그동안 운행은 멈춥니다.
- **브레이크**(₩80)는 평평한 조각으로, 속도를 일정 수준(약 48km/h)까지로 눌러 줍니다. 코스의 강도가 낮아집니다.
- **루프**(₩200)는 앞으로 한 칸, 높이 변화 없이 수직 원을 도는 조각입니다. 진입 속도가 충분해야 하며(약 52km/h 이상) 부족하면 "속도가 부족해 루프를 못 넘음" 오류로 그 조각에서 코스가 완성되지 않습니다. 재미와 강도를 크게 올리지만 멀미도 늘고 에너지를 더 깎습니다. 루프는 아래 위로 2단계(높이 h~h+2)를 차지하고, 꼭대기가 높이 제한(8)을 넘을 수 없습니다.
- **트랙 교차**: 같은 칸을 지나는 두 트랙(같은 코스터든 다른 코스터든)은 높이 구간이 **2단계 이상** 떨어져 있으면 허용됩니다. 길 위는 조각의 가장 낮은 높이가 2 이상일 때만 지나갈 수 있고, 길은 그대로 걸어 다닐 수 있습니다. 건물·건물 입구 칸 위에는 놓을 수 없으며, 지나가는 트랙 아래에는 건물을 지을 수 없습니다. 지지대는 아래 트랙 위에서 끝나고 길 위에는 세워지지 않습니다. 높이는 0~8단계입니다.
- **시운전**: 건물 패널과 트랙 편집 바의 `시운전` 버튼으로 손님 없이 열차를 한 바퀴 달려 볼 수 있습니다(편집 중에도 가능). 미완성이거나 도중에 멈추는 코스는 멈추는 지점까지 달리고 그 자리를 표시합니다. 화면 연출일 뿐이며 저장되지 않습니다. 역 입구는 진행 방향 오른쪽 옆면에 있으니, **오른쪽으로 감는 루프는 입구를 안쪽에 가둘 수 있습니다.**
- **속도는 에너지로 계산합니다.** 내리막은 속도를 더하고 오르막은 깎으며 조각마다 마찰이 조금씩 깎습니다. 체인 리프트는 에너지와 상관없이 일정 속도로 올려 줍니다. 열차가 멈추는 코스(리프트 없이 오르기만 하거나 너무 긴 평지)는 완성되지 않고 어느 조각에서 멈추는지 알려 줍니다.
- 완성된 코스에서 **재미**(낙차·길이·회전·높이), **강도**(최고 속도·낙차·빠른 회전), **멀미**(연속 회전·오르내림)와 한 바퀴 시간이 계산됩니다. 강도가 75를 넘으면 손님이 덜 즐거워하고, 85를 넘으면 "너무 무서워!"라고 하며, 멀미가 높으면 에너지가 더 깎입니다. 처음 완성될 때 요금은 적정가로 맞춰집니다.
- 비용: 역 ₩800, 조각 ₩60(리프트 ₩100). 유지비는 역 ₩100 + 조각당 ₩10. 철거하면 쓴 돈의 50%를 돌려받습니다.

**지형**
- 땅의 높이는 칸마다 0~4단계이고, 새 공원은 평지입니다. 툴바 `지형`의 `지형 올리기`/`지형 내리기`로 클릭하거나 드래그해 한 칸당 ±1단계씩 바꿉니다(칸당 ₩20, 환급 없음).
- **이웃한 칸(상하좌우)과의 높이 차는 1단계까지만** 허용합니다. 언덕은 한 층씩 쌓아야 하고, 어기는 변경은 안내 문구와 함께 거절됩니다. **길·건물·건물 입구 칸·낮게 깔린 트랙이 있는 칸**은 바꿀 수 없고, 철거해도 지형은 그대로입니다.
- **길**은 어느 높이에나 깔 수 있지만, 이웃한 두 길은 높이 차가 **1 이하**일 때만 이어집니다(차 1은 경사로로 걸어 다닐 수 있음). 차가 2 이상이면 끊긴 길이라 그 너머 건물은 운영되지 않습니다.
- **건물**은 풋프린트와 입구 칸이 모두 같은 높이(평평한 땅)여야 지을 수 있습니다. 롤러코스터 역도 같습니다.
- **트랙 높이는 지형과 같은 단위의 절대 높이**입니다. 조각의 가장 낮은 높이가 그 칸의 지형보다 낮으면(땅속) 놓을 수 없습니다. 코스는 역이 서 있는 땅 높이에서 출발해 그 높이로 돌아와야 하며, 역을 언덕 위 평지에 지어도 됩니다(통계의 최고 높이는 역 기준). 장식은 어느 높이에나 심을 수 있습니다.

**장식**
- 툴바 `장식`에서 침엽수·활엽수·꽃밭을 빈 잔디에 심을 수 있습니다(길처럼 드래그로 한 줄씩). 새 공원은 가장자리에 숲이 있습니다.
- 길가 8칸 안에 나무나 꽃이 있으면 지나가는 손님의 기분이 조금씩 좋아지고 "경치가 좋네"라고 말합니다.
- 길·건물·트랙을 그 위에 지으면 장식은 저절로 치워지고, 철거 도구로는 환급 없이 치울 수 있습니다.

**쓰레기와 청소부**
- 햄버거·음료를 산 손님은 이용을 마치고 3~8초(30~80틱) 안에 쓰레기를 버립니다. 반경 3칸 안에 **쓰레기통**(장식 도구, ₩50)이 있으면 거기에 버리고, 없으면 서 있는 길에 버려 길 한 칸에 최대 3개까지 쌓입니다. 쓰레기통은 잔디 위에 놓고, 경치 보너스는 주지 않습니다.
- 주변 2칸 안의 쓰레기가 많으면 손님이 기분이 나빠지며 "너무 더러워!"라고 하고, 평점의 **청결** 항목이 깎입니다(길이 깨끗하면 감점 없음, 최대 −100).
- 툴바 `직원` 그룹의 `청소부 고용`으로 청소부를 부릅니다. 하루 급여는 한 명당 ₩60이고 재무 보고서에 `직원 급여`로 나옵니다. 청소부는 가장 가까운 더러운 길로 가서 20틱(2초) 동안 쓸어 치우고, 할 일이 없으면 길을 어슬렁거립니다. 청소부를 클릭해 `해고`할 수 있습니다.

**정비공과 고장**
- 놀이기구(매점 제외)는 운행을 한 번 마칠 때마다 **신뢰도**가 1.5씩 줄어듭니다(처음 100). 운행이 끝날 때 신뢰도가 낮을수록 고장 날 확률이 커집니다(확률 = (100 − 신뢰도) / 400, 운행 횟수로 정해지는 결정적 판정이라 같은 상황이면 같은 결과).
- 고장 나면 입구에 빨간 **렌치** 아이콘이 뜨고 건물 패널에 `고장`으로 표시됩니다. 운영 불가 상태가 되어 새 손님을 받지 않고, 줄 서 있던 손님은 "고장났네…"라며 돌아섭니다.
- 툴바 `직원` 그룹의 `정비공 고용`(하루 ₩60)으로 정비공을 부릅니다. 정비공은 아무도 맡지 않은 고장 난 기구의 입구로 가서 60틱(6초) 동안 수리하고, 수리가 끝나면 고장이 풀리며 신뢰도가 +30(최대 100) 회복됩니다. 고장이 없으면 신뢰도가 80 미만인 기구 중 가장 낮은 곳을 30틱(3초) 점검해 +10 회복시키고, 그것도 없으면 길을 어슬렁거립니다.
- 건물 패널의 `신뢰도`로 상태를 확인할 수 있습니다. 고장 난 기구는 운영 중으로 치지 않아 평점과 손님 유입에도 불리합니다.

**손님**
- 손님은 행복·배고픔·갈증·화장실·에너지 욕구를 가지고, 욕구와 재미·거리·대기열·요금을 따져 갈 곳을 고릅니다.
- 줄이 너무 길면(15명) 포기하고, 오래 기다리면(약 40초) 줄에서 나가며 불만이 쌓입니다.
- 머리 위 말풍선과 손님 패널로 지금 무슨 생각을 하는지 볼 수 있습니다.
- 행복이나 에너지가 바닥나거나 돈이 떨어지면 공원을 떠납니다.

**경제**
- 수입: 입장료, 놀이기구 요금, 매점 매출. 지출: 건설비, 건물별 하루 유지비.
- 하루는 1배속 기준 60초, 한 달은 10일입니다. 달이 끝나면 월간 보고서가 열립니다(`재무` 버튼으로 언제든 확인).
- 요금이 **적정가**보다 비싸면 손님이 그 시설을 덜 찾고, 입장료가 비싸면 입장하는 손님이 줄어듭니다. 너무 싸게 받아도 손해이니 균형점을 찾아보세요.

**평점 (0~1000)**
- 만족도, 시설 다양성, 대기열 흐름, 불만(배고픔 등 해결되지 않은 욕구)을 합산해 서서히 변합니다. 상단의 평점에 마우스를 올리면 항목별 점수가 보입니다.
- 평점이 높을수록 손님이 더 많이 찾아옵니다.

**저장**
- 15초마다, 그리고 탭을 닫거나 숨길 때 브라우저(`localStorage`)에 자동 저장합니다. `저장` 버튼으로 수동 저장도 됩니다.
- 읽을 수 없는 저장 데이터는 덮어쓰기 전에 백업됩니다.

**날씨**
- 날씨는 하루 단위로 정해집니다: 맑음 55% · 흐림 25% · 비 20%. 첫날은 항상 맑고, 이후는 `hash32(시드, 날짜)`로 정해져 저장·불러오기 후에도 같습니다. 상단 `#rating` 옆에 ☀️/☁️/🌧가 표시됩니다(마우스를 올리면 설명).
- **비 오는 날**: 손님 입장 확률이 −30%가 되고, 우산이 없는 손님은 **실외 놀이기구**(회전목마·관람차·범퍼카·롤러코스터)를 꺼려 점수에서 크게 감점합니다. 우산 없이 시설 밖에 있으면 3초마다 행복이 1씩 줄며 "비가 와…"라고 합니다.
- **우산 가게**(매점, ₩300): 비가 올 때 우산이 없는 손님만 찾아오고, 사면 그 손님은 비 페널티가 없습니다(우산을 쓴 모습으로 그려집니다).
- 화면은 비가 오면 어두워지며 빗줄기가 내리고, 흐린 날은 살짝만 어두워집니다.

## 구조

```
src/
  sim/        게임 규칙. DOM·Canvas를 전혀 모르는 순수 로직 (테스트 대상)
    world.ts       상태(맵, 건물, 손님, 돈, 장부, 평점, 목표 상태)
    guest.ts       손님 욕구와 상태머신, 말풍선 생각
    pathfinding.ts 길 그래프 BFS, 경로 캐시, 입구 연결 판정
    ride.ts shop.ts venue.ts   놀이기구 사이클, 매점 응대, 대기열
    coaster.ts trackedit.ts    롤러코스터 트랙 모델·물리·스탯, 조각 잇기/되돌리기
    economy.ts rating.ts goals.ts spawner.ts   달력·정산, 평점, 목표/파산, 입장
    tutorial.ts    시작 가이드 단계 판정
    weather.ts     하루 단위 날씨(결정적), 비 효과 상수
    staff.ts       직원(청소부·정비공) 고용·이동·청소·수리·점검
    sim.ts         한 틱의 진행 순서
  render/     아이소 좌표 변환(iso.ts: 높이 단위·`tileToWorldZ`), 카메라, 캔버스 그리기(sprites.ts: 놀이기구·나무 모양, ground.ts: 지면 조각 캐시, relief.ts: 칸 윗면의 모서리 높이·비탈)
  input/      마우스·키보드 입력, 도구 컨트롤러(설치/철거/선택), pick.ts(높이를 고려한 칸 피킹)
  ui/         HUD, 툴바, 패널, 모달, 효과음 (DOM)
  save/       버전이 있는 저장 형식, 직렬화, 저장소 접근
  data/       놀이기구·매점 정의 표 (밸런스는 여기서 조정)
  core/       고정 틱 루프, 시드 고정 난수, `hash32`(RNG를 쓰지 않는 결정적 해시)
tests/        Vitest 단위 테스트
```

설계 메모:
- **시뮬레이션과 렌더링 분리.** 시뮬레이션은 고정 간격(초당 10틱)으로 진행하고 화면은 `requestAnimationFrame`마다 틱 사이를 보간해 그립니다. 배속은 틱 횟수만 바꿉니다.
- **결정적 시뮬레이션.** 난수는 시드 고정(`core/rng.ts`)이라 같은 상태에서 같은 결과가 나옵니다. 그래서 "저장 후 불러와서 계속 진행한 결과가 원본과 같다"를 테스트로 보장합니다.
- **새 기능은 `world.rng`를 쓰지 않습니다.** 쓰레기 시점이나 청소부 배회처럼 "무작위"가 필요한 곳은 `(tick+id)%N` 위상이나 `hash32`를 써서 난수열이 밀리지 않게 합니다. 쓰레기는 지면 캐시와 분리해 매 프레임 겹쳐 그립니다.
- **날씨 시드.** `world.weatherSeed`는 새 게임 때 정해지고(`world.rng`를 소비하지 않음) 저장됩니다. `new World()`와 날씨 정보가 없는 저장본은 처음 12일간 비가 오지 않는 기본 시드를 써서, 짧은 시뮬레이션 테스트가 날씨에 흔들리지 않습니다.
- **저장은 v4.** 지형 레이어(`terrain`, 칸마다 한 글자)·쓰레기 레이어·직원·급여·날씨·우산은 모두 선택 필드라 v1~v3 저장본도 기본값으로 읽힙니다.
- **밸런스 조정 지점.** 건물 비용·요금·유지비는 `src/data/`, 목표 수치는 `src/sim/goals.ts`(`GOAL`), 시간 단위와 입장료 곡선은 `src/sim/economy.ts`, 코스터 물리·조각 비용은 `src/sim/coaster.ts`(`PHYSICS`, `PIECE_COST`)에 있습니다.

## 테스트와 개발용 훅

- `npm test`는 좌표 변환, 건설 규칙, 길찾기, 손님 AI, 대기열, 경제, 평점, 목표, 저장/불러오기, 말풍선과 선택, 쓰레기·쓰레기통·청소부·급여, 날씨(분포·비 효과·우산·저장), 롤러코스터(조각 잇기·완성 판정·물리·스탯·저장), 시작 가이드 판정을 다룹니다.
- `npm run e2e`는 헤드리스 Chromium으로 길 드래그 → 건설 → 손님 입장·이용·수익 → 저장/새로고침 복원, 롤러코스터를 키보드로 설계·완성해 손님을 태우고 저장/복원하는 것, 지형 도구 클릭·드래그와 높이 보정 호버까지 확인하고 스크린샷을 `e2e-out/`에 남깁니다(Playwright는 환경에 설치된 것을 사용).
- `npm run perf [손님 수]`는 손님 500명·건물 10개·롤러코스터 2대·언덕 지형에서 시뮬레이션 1틱과 렌더 1회 시간을 잽니다. 소프트웨어 렌더링 헤드리스 기준 측정값: 1틱 약 0.2ms, 렌더 1회 약 10ms(지면 약 4ms + 손님 500명 + 트랙)로 프레임당 16ms 예산 안입니다. 실제 GPU 브라우저에서는 더 여유롭습니다. (측정 시작 직후 한두 프레임이 튀어 평균이 커 보일 수 있어 중앙값·p95를 함께 봅니다.)
- **지형 렌더링과 피킹.** 높이 1단계 = 코스터 트랙 1단계 = `LEVEL_PX`(26px)로 지형과 트랙이 같은 단위입니다. 지면 조각(`ground.ts`)은 솟은 칸을 뒤→앞 순서로 윗면 + 앞쪽 두 변의 절벽 옆면으로 그리고(길은 높이 차 1인 이웃 길 쪽으로 기운 경사면), 조각 캔버스는 그 조각의 최고 높이만큼 위쪽 여유를 둡니다. 길·지형을 고치면 칸 내용 해시가 달라진 조각만 다시 그립니다. 건물·장식·손님·직원·말풍선·선택 링·호버는 지면 높이(`groundHeightAt`/칸 높이)만큼 올려 그리고, 트랙 지지대는 그 칸의 지면까지 내려옵니다. 마우스 아래 칸은 `pickTile`이 시선을 따라 높은 곳에서 내려오며 처음 닿는 지표면(윗면·절벽 포함)으로 정하므로, 언덕 뒤에 가려진 칸은 클릭되지 않습니다. 언덕 뒤에 선 손님·직원·건물은, 그것을 가리는 솟은 칸(`occludingTiles`)을 물체 뒤에 다시 그려(`paintTerrainTile`) 언덕 앞면 위로 비치지 않게 합니다. 솟은 칸이 없는 공원에서는 이 과정을 통째로 건너뜁니다. 경사 길의 모서리 높이는 꼭짓점마다 하나로 정해(이어진 길 칸 높이의 평균, `relief.ts`) 이어진 두 칸의 맞닿은 변이 항상 맞습니다(`tests/seam.test.ts`). 알려진 한계: 다시 그리는 칸 위의 선택 링·입구 표시 같은 바닥 표식은 그 칸에서 가려질 수 있습니다.
- 개발 서버(`npm run dev`)에서만 `window.__game`(`world`, `step(n)`, `spawn(n)`, `tileToScreen`, `hover`, `focus`, `render` 등)이 노출됩니다. 시간을 빨리 감아 볼 때 쓰며 프로덕션 빌드에는 포함되지 않습니다.
